# 2026-10-03：语音日志与保护性修复收尾

## 已部署

- `[voice.trace]` 按 task_id 记录录音开始、结束事件接收、VAD、识别路径、最终结果、输出调用及耗时；不新增音频或识别全文留存。
- 输出层按任务读取 SNR/VAD 数据，不再使用下一句的全局电平；判定记录最多保留 128 条，结果消费后回收。
- VAD 导入、加载和推理失败均跳过 VAD，保留其他既有判据，不让诊断或模型故障直接中断整句。
- 统一两层 VAD 判定，正确处理 ratio=0.0；统一返回字段，模型路径不依赖工作目录。
- 当前阈值、峰值归一化与用户认可的黄色圆底/白色感叹号动画不变。

## 时间与状态口径

- release 是录音协程收到结束事件的时间，不是物理松手的精确时间。
- output_returned 是输出调用返回，不保证目标应用实际接收了文字。
- asr_route 记录云端/本地的概况；具体候补故障仍需结合 cloud_asr 日志，不把所有空结果都解释为超时。
- 日志不能单独证明识别文字符合原话，也不能据此推断零误杀。

## 后续只在实际异常出现时关注

- 正常说话却出现黄色警示：核对 task_id、电平、语音时长、占比和具体拦截条件，尤其长按短说的低占比场景。
- 静默/敲击仍输出文字：核对归一化增益、VAD 概率和识别路径。
- 警示后迟到结果又上屏、连续句子错配：核对任务判定记录及最终结果到达顺序。
- 识别完成但输入框无字：输出返回不等于上屏成功，结合输入焦点及剪贴板/模拟打字路径检查。
- 非部署期间反复本地服务断连、VAD 加载失败、绘制停帧或明显延迟：按最近日志定位，不把旧事故报错当新故障。

## 明确暂缓，不是待办承诺

用户决定保留当前可用体验，不为工程标准继续改动：
- 第二优先级第二批：官方 64 样本上下文、尾帧补零、占比门槛调整、连续语音片段与归一化评测。
- 第三优先级：先判定再发送、进一步取消/迟到结果处理。
- fork README 的迭代与特性整理也暂缓。

这些仅在实际问题或新明确需求出现时重新评估。此前“最新版模型失效”的判断受非标准调用影响，不能当成模型能力结论。
